# stopwatch-factory

PocketJS recreation of the M5Stack StopWatch (C152) factory firmware,
[m5stack/M5StopWatch-UserDemo](https://github.com/m5stack/M5StopWatch-UserDemo)
at `81099c784991dc77f522de1a5bf62ec5de9ae0b5` (main, 2026-10-29). The same
TSX/TS sources build in JS mode (QuickJS bundle) and in AOT mode (MicroTS);
`pocket.host.config.ts` sets `aot: true` and `model: "compiled"`.

The host config lives here because the Pocket CLI resolves the entry
relative to the config and rejects `..`; it names the program's host
contract, `../../programs/stopwatch/pocket.host.json` (466 × 466, 30 Hz,
`input.buttons`, `input.touch`, `text.glyphs.baked`).

## Files

| File | Content |
| --- | --- |
| `main.tsx` | JS-mode `mount()` entry |
| `app.tsx`, `app.ts` | Root view and root model; `app.ts` owns every rendered signal and runs the frame task |
| `device.ts` | Device data bridge state: every host value (clock, battery, raw keys and pointer, IMU, spectrum, settings, alarms) and every host request (tones, vibration, RTC, settings, …) |
| `input.ts` | Key manager (click, hold, A+B home) and pointer tracking on the raw device fields |
| `motion.ts` | Springs (smooth_ui_toolkit visual duration / bounce) and the LVGL ease-out curve |
| `launcher.ts`, `statusbar.ts`, `watch.ts`, `stopwatch.ts`, `alarms.ts`, `setup.ts`, `wheel.ts`, `imu.ts`, `fft.ts`, `badge.ts`, `fluid.ts` | Per-app logic in state modules |
| `roller.ts` | lv_roller behaviour (drag, glide, snap, tap, wrap) for up to three pickers |
| `*View.tsx`, other `*.tsx` | Presentational child views; they receive values and callbacks as props. A view that shares its name with a logic module carries a `View` suffix: on a case-insensitive file system `Stopwatch.tsx` would otherwise take `stopwatch.ts` as its basename model |
| `images/`, `images.json` | Factory artwork converted to power-of-two PNG textures |
| `scripts/import-factory-assets.ts` | Regenerates `images/` and `images.json` from a factory checkout |
| `scripts/gen-big-number.ts` | Regenerates `BigNumber.tsx` |
| `DigitStrip.tsx`, `Glyphs*.tsx`, `glyphs.ts` | Generated by `scripts/gen-glyphs.ts`: factory glyph images and their advances |
| `textlayout.ts` | Pen positions of glyph-image text |
| `pocket.fonts.json`, `fonts/` | Declared faces and font licences |

State modules cannot declare signals in MicroTS, so the per-app modules
keep plain fields and `app.ts` copies their results into signals once per
frame. Gestures (carousel drag, swipes, list scrolling, long presses) are
model code driven by `device.pointerDown/X/Y`, so they behave the same in
both modes.

`main.tsx` connects the JS-mode bridge (`connectDevice`, docs/APP-HOST.md);
`app.ts` re-exports the host entry points of `device.ts`. The board
(`programs/stopwatch/main/services.c`) publishes the clock, keys, battery,
IMU, microphone spectrum, settings and alarms, and handles the requests
`tone`, `vibrate`, `brightness`, `volume`, `button_sfx`, `button_vibrate`,
`wifi`, `rtc`, `guide_count`, `boot_sfx`, `mic`, `alarm_clear`/`alarm`/
`alarm_save`, `badge_slot`, `badge_edit` and `alarm_ring`.

Without a board (`device.bridged` false until `uptimeMs` arrives) the app
advances its own clock from the frame count and takes key clicks from
`ActionHandler` presses (LTRIGGER = KEYA, RTRIGGER = KEYB).

## Differences from the factory firmware

- Fonts: text at the PocketJS slot sizes uses the factory's Montserrat
  Medium and SemiBold at the nearest slot; Maple Mono and Commissioner text
  at other sizes is drawn with the factory's own glyph bitmaps as images
  (see [Fonts](#fonts)).
- Number flow digits roll like smooth_ui_toolkit 2.12.1 `DigitFlow`
  (strip 9,0..9,0, spring with visual duration 0.6 s and bounce 0.05, up
  when the value grew, down when it shrank, velocity kept across the wrap).
  With a turned face the three tiles and their 66 px digit windows stay
  upright and only move with the face (see the watch-face item below), so
  the digits do not turn and roll along the screen's vertical axis.
- Images: PocketJS textures are power-of-two and at most 512 px, so the
  artwork sits on padded canvases (icons and the guide are stored as
  RGB565, the big-number digits as one RGBA4444 tile per palette colour and
  digit, 3.7 MB of the bundle).
- The watch face turns with the accelerometer as one 466 px panel about the
  screen centre, as the factory turns its panel (`watch_face_manager.cpp`).
  Ticks, hands, time digits, date pill, big-number digits, the simple-face
  dot and the text baselines turn with it. Differences:
  - The number-flow tiles and digit windows are not in the panel. A digit
    window is `overflow-hidden`, and PocketJS clips a turned subtree to the
    axis-aligned bounds of the turned window, which shows the neighbouring
    rows of the rolling strip. The tiles stay upright with their windows and
    the model moves them by the turned offsets of their centres; the date
    below them turns with the panel and is drawn above them.
  - Montserrat text (classic weekday and date pill, number-flow and simple
    date, simple tips) keeps upright glyphs placed along the turned baseline:
    PocketJS draws a glyph run under a turned transform with upright,
    unscaled glyph cells (pocketjs issue #728). At 90° the letters stack
    vertically, at 180° a word reads backwards ("NUS"), and at both the
    date-pill digits sit partly outside the pill. The factory turns the
    glyphs. The time digits are images and turn.
  - The face backgrounds and the classic dial are drawn outside the panel;
    they look the same at every angle. A turned rounded box is drawn as a
    polygon with four segments per quarter circle (pocketjs #322); the
    facets would show on the 358 px dial and on the number-flow tiles
    (radius 42), not on the 34 px date pill or the 14 px second dot, which
    turn.
- Lucky wheel sectors are drawn as rotated half-planes clipped to the two
  screen halves; the factory draws LVGL arcs. Bar spectrum wedges are
  rectangles 12 px wide instead of triangles.
- The rollers are 164 px tall everywhere (the factory day roller is 220 px)
  and glide for a fixed 300 ms of the release velocity.
- Settings sub-pages are left with A+B (as in the factory) and the menu
  scroll has no momentum.
- Alarm list order, limits and storage follow the factory (NVS namespace
  `alarm`, 68-byte blob), so alarms set by the factory firmware load.
- The badge editor screen can also be left with A+B (the factory waits only
  for the web page's Close).
- The badge picture is a run-time texture: the board decodes the active
  JPEG (scaled by 1/2, 1/4 or 1/8 when larger than 466 px) onto the smallest
  power-of-two RGB565 canvas that holds it and registers it under
  `images/badge_slot.png` with `m5_pocket_app_set_texture` in both modes
  (in JS mode `connectDevice` binds it). The view hides the image for one
  frame when the published handle changes so the node binds the new
  texture.

## Fonts

`pocket.fonts.json` (docs/FONTS.md) declares the faces `tools/pocket`
bakes in both modes:

| Role | Face | File | Version / source | Licence |
| --- | --- | --- | --- | --- |
| `regular` | Montserrat Medium | `fonts/Montserrat-Medium.ttf` | Version 9.000, [JulietaUla/Montserrat](https://github.com/JulietaUla/Montserrat) `fonts/ttf/` at `555facfb2a18c72c3c0380f0d9c0f060453a9058` | SIL OFL 1.1, `fonts/Montserrat-OFL.txt` |
| `bold` | Montserrat SemiBold | `fonts/Montserrat-SemiBold.ttf` | as above | as above |
| `mono` | not declared | | The factory's Maple Mono sizes (24, 28, 48 px) are not mono slots (12/14/16 px) | |

The files are unmodified. The factory draws Montserrat Medium for body text
and SemiBold 26 px for titles; PocketJS has no medium/semibold utility, so
Medium is `regular` and SemiBold is `bold`.

Factory sizes and what the app uses:

| Factory text | Factory size | Here |
| --- | --- | --- |
| Montserrat 10, 14, 16, 18, 20, 24, 36 | same | exact slot (`text-2xs` … `text-4xl`) |
| Montserrat 22 (status text) | 22 | nearest slot, 20 px |
| Montserrat 28 (rollers, buttons, OK, boot title) | 28 | nearest slot, 24 px |
| Montserrat SemiBold 26 (titles) | 26 | nearest slot, 24 px `font-bold` |
| Maple Mono Medium 24 (weekday, date pill, stopwatch buttons) | 24 | 24 px slot of Montserrat Medium |
| Maple Mono Medium 28 (arc top clock, classic time, laps) | 28 | glyph images |
| Maple Mono Medium 48 (stopwatch time) | 48 | glyph images |
| Commissioner Medium 64 (number-flow digits) | 64 | glyph images |
| Commissioner Medium 108 (simple face, alarm trigger, brightness/volume value, ":(") | 108 | glyph images |

Glyph images: `scripts/gen-glyphs.ts` reads the factory's LVGL bitmap fonts
(`main/assets/fonts/lv_font_maple_mono_medium_28.c`, `..._48.c`,
`CommissionerMedium64.c`, `CommissionerMedium108.c`, 2 bpp, rendered by the
factory with lv_font_conv from Maple Mono Medium and Commissioner Medium,
SIL OFL 1.1: `fonts/MapleMono-OFL.txt`, `fonts/Commissioner-OFL.txt`) and
writes every glyph the app shows, cropped to its ink, recoloured to each
colour it is shown in (images take no text colour), as RGBA4444 on
power-of-two canvases; glyphs taller than 64 px are two tiles. It also
writes `glyphs.ts` (advances for the model's layout in `textlayout.ts`),
the `Glyphs*.tsx` views (one per font and colour, one `<Show>` per glyph and
slot) and `DigitStrip.tsx`. Colour sets: Maple Mono 28 in white, #CDEBF9,
#D9D9D9, #D8F2FF and #738086; Maple Mono 48 in #D8F2FF; Commissioner 64
and 108 in the ten theme time colours (theme 0 is white, which also serves
the trigger, slider value and ":("). 408 images, 1,812,480 bytes. Run
`scripts/import-factory-assets.ts` first, then `scripts/gen-glyphs.ts`
(the asset import rewrites `images/` and `images.json`).

The root model publishes the codepoints and pen positions of every
glyph-image text as array signals (`clockIds`, `swTimeIds`, `swTimeXs`, …
in `app.ts`) and lays a text out when it changes. A glyph view reads its
`ids` and `xs` in every `<Show>`; a compiled view reads a signal in place
and evaluates a call again at each use, so `ids={glyphIds(text())}` laid
the text out once per glyph and slot: 2,083 heap allocations and 20 ms per
frame on the stopwatch page, 70 allocations and 3.7 ms with the signals
(StopWatch, AOT).

## FluidBox limit

The factory simulates 450 particles with a 3D double-density SPH at 80 Hz
in C on its own task (neighbour grid, up to 14,400 pairs) and paints them
directly into the framebuffer at 25 Hz from the other core. Here the
simulation is model code (QuickJS in JS mode) on the app task, which also
lays out and rasterises the frame at 30 Hz, and every particle is a UI node.
Estimate, not measured on a device: 48 particles cost about 4,500 pair
evaluations per frame (two passes, two sub-steps); 450 particles with the
factory's grid cost about 13 times more, and each frame would also update
about 1,350 node properties and repaint the full 466 × 466 frame. At the
interpreter speeds of QuickJS on a 240 MHz S3 that is several times the
33 ms frame budget, so the JS-mode app keeps 48 particles. AOT mode runs the
same model as compiled Rust; a larger count there still pays the per-node
drawing cost.
- The 1-column offset between the factory 468-column frame and the
  466-column frame used here moves the content by at most 1 px.
- Wi-Fi icon in the status bar: not shown (Wi-Fi is not implemented).
